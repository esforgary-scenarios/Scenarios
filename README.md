# Кадр — сценарии

Адаптивное приложение на русском языке для сценариев роликов. Работает на GitHub Pages, авторизация и личные данные — в Supabase. Платный сервер не нужен.

## Возможности

- На главном экране есть отдельная вкладка «Цитаты»: общая коллекция фраз для будущих роликов с поиском, редактированием, удалением и копированием. Длинные фразы свёрнуты до четырёх строк и раскрываются кнопкой. Цвет значка кавычек можно выбрать; доступны фильтр и сортировка по цвету. Карточки сохраняют переносы строк; цитаты хранятся в аккаунте независимо от списка роликов.
- Главный экран — список роликов; сценарий открывается отдельно, без боковой панели. Создание, удаление, поиск, фильтры, отметка «Снято», перетаскивание с удерживанием. Для клавиатуры: фокус на ручке, пробел, стрелки, пробел. Также есть перемещение через меню ролика.
- Превью хранится отдельно от галереи и отображается между номером и названием в списке. Прежние данные автоматически переносятся в этот формат без удаления файлов.
- Редактор с выбором шрифта, размера, жирного, курсивного и подчёркнутого начертания; списками, выравниванием, отменой и повтором. По умолчанию текст выровнен по ширине, межстрочный интервал — 1,45.
- Тёмная палитра GitHub, короткие анимации действий и поддержка системной настройки уменьшения движения.
- Автоматическая подсветка парных `"кавычек"`, `«ёлочек»`, `“двойных кавычек”` зелёным и `*текста*` / `**текста**` оранжевым, в том числе через фрагменты с разным форматированием внутри одного абзаца. Парные маркеры удаляются, а подсветка сохраняется вместе со сценарием. Жирный и курсив включаются кнопками или Ctrl+B / Ctrl+I.
- Один растущий лист сценария без пагинации, счётчик слов и приблизительное время чтения.
- У каждого ролика вкладки «Сценарий», «Галерея», «Ссылки», «Описание» и «Теги». Переключение вкладок сохраняет состояние редактора и историю отмены. Ссылки на сайты можно подписывать, дополнять заметкой, редактировать, копировать и удалять.
- Название — до 100 символов, описание для вставки в YouTube Studio — до 5000, с переносами строк, ссылками и форматированием. Теги вводятся через запятую или Enter и копируются одним списком. Счётчик тегов учитывает лимит 500 символов, запятые и дополнительные кавычки у тегов с пробелами. Описание и теги сохраняются отдельно для каждого ролика; старые данные загружаются без обрезки. Ограничения: [YouTube Studio](https://support.google.com/youtube/answer/57404), [подсчёт тегов](https://developers.google.com/youtube/v3/docs/videos#snippet.tags%5B%5D).
- Кнопки «Цитата» и «Действие» после подчёркивания включают или снимают подсветку выделенного текста и дальнейшего ввода. Горячие клавиши: Ctrl+Shift+1 и Ctrl+Shift+2 (цифры в верхнем ряду, работают и в русской раскладке).
- Загрузка изображений из файлов, перетаскиванием или Ctrl+V. Названия, выбор изображения на превью, удаление. PNG/JPG/WebP/GIF до 10 МБ на файл.
- При вставке изображения с HTTPS-адресом сохраняется только URL. Есть отдельная кнопка «По ссылке»; файлы и скриншоты без адреса загружаются в хранилище. Внешние изображения доступны, пока исходный сайт отдаёт их по сохранённой ссылке.
- Автоматическое сохранение с индикацией ошибок. Защита от незаметного перезаписывания изменений с другого устройства.
- Вход по почте и паролю. «Запомнить меня» сохраняет вход на 40 дней с момента входа, без продления при обновлении токена. Без галочки хранение сессии ограничено вкладкой браузера.

## Локальный запуск

Нужен Node.js 22.12+ (рекомендуется 24).

```sh
npm ci
npm run dev
```

Для входа требуется настроенный Supabase и переменные окружения, описанные ниже. Приложение не использует фиктивные пароли и не сохраняет пароль аккаунта.

## Бесплатный Supabase

1. Зарегистрируйтесь на [supabase.com](https://supabase.com/dashboard). Создайте организацию с тарифом **Free** и проект. Пароль базы сохраните у себя.
2. Откройте **SQL Editor**, создайте новый запрос и выполните весь файл [supabase/schema.sql](supabase/schema.sql). Он создаёт таблицу сценариев, закрытое хранилище изображений и правила доступа. Не отключайте RLS и не делайте bucket публичным.
3. В **Authentication → Users → Add user → Create new user** создайте свой аккаунт с почтой и паролем. Если предлагается **Auto Confirm User**, включите его. Для личного приложения отключите публичную регистрацию в настройках Auth. Аккаунт приложения и пароль базы — разные вещи.
4. Найдите **Project URL** и **Publishable key** в диалоге **Connect** либо в настройках проекта API / API Keys. Публичный ключ выглядит как `sb_publishable_…`. Не используйте `sb_secret_…`, `service_role` или пароль базы в клиентском приложении.
5. Скопируйте `.env.example` в `.env.local` и заполните:

```dotenv
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_your_key
```

6. Перезапустите `npm run dev` и войдите созданными почтой и паролем.

Переменные `VITE_*` доступны в сборке браузера по устройству Vite. Это нормально для публичного ключа Supabase: доступ к данным ограничивается пользователем и серверными политиками RLS. Секреты туда помещать нельзя.

На бесплатном тарифе на момент подготовки доступны 500 МБ базы и 1 ГБ файлов. Малоактивные проекты могут приостанавливаться после 7 дней; восстановление выполняется в панели Supabase. Актуальные условия: [тарифы](https://supabase.com/pricing), [пауза бесплатных проектов](https://supabase.com/docs/guides/platform/free-project-pausing).

## Публикация на GitHub Pages

1. Создайте репозиторий GitHub и загрузите исходные файлы проекта. Не загружайте `node_modules`, `.env.local`, `.npm-cache` и `dist`.
2. В репозитории откройте **Settings → Secrets and variables → Actions → Variables**. Создайте две repository variables: `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY` со значениями из `.env.local`.
3. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**.
4. Отправьте изменения в `main` или `master`, либо запустите **Actions → Deploy to GitHub Pages → Run workflow**.
5. После успешной сборки адрес появится в **Settings → Pages**. Приложение работает и на `username.github.io`, и по пути `username.github.io/repository/`.
6. Установите опубликованный адрес в **Supabase → Authentication → URL Configuration → Site URL**. Для обычного входа по паролю редиректы не нужны; настройка пригодится для писем восстановления, которые можно отправлять из панели Supabase.

При смене URL/ключа нужна новая сборка. Сценарии и картинки не попадают в репозиторий: они остаются в Supabase.

## Особенности хранения

Проект фоторедактора сохраняется внутри своего ролика: размеры холста, слои, текст, маски и настройки эффектов остаются редактируемыми. Исходные изображения хранятся в закрытом bucket отдельно от галереи; экспорт в галерею создаёт самостоятельный готовый PNG. Коллекция Google Fonts хранится в поле `workspaces.fonts` и доступна во всех роликах аккаунта. Для обновления существующей базы повторно выполните `supabase/schema.sql`: поле добавляется без перезаписи сценариев. В JSON сохраняются пути к приватным файлам, временные `blob:`-адреса заново создаются после входа.

В облаке каждый пользователь видит только собственную рабочую область. Картинки скачиваются с авторизацией из закрытого bucket; объектные URL действуют в текущем браузере. Серверные политики дополнительно ограничивают доступ сессиями младше 40 дней. Выход очищает вход на этом устройстве. Browser session storage может восстанавливаться самим браузером при восстановлении вкладок; гарантированный выход выполняется кнопкой выхода.

При одновременном редактировании с нескольких устройств устаревшее сохранение отклоняется. Если приложение сообщает о конфликте, сохраните нужный текст через меню «Скачать текст» и обновите страницу, прежде чем продолжать работу. При сбое сохранения не закрывайте вкладку: изменения остаются в памяти до успешного повтора, браузер предупредит о несохранённых данных.
